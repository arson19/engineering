# Engineering by Prabhav — GitHub Pages

A responsive, static technical blog with three starter articles. The public pages intentionally omit visible publication dates and times.

## Included

- Responsive landing page and article navigation
- Three independently written starter articles:
  - From Kubernetes YAML to Helm Charts
  - Building a Canary Deployment Pipeline
  - Thinking Through Multi-Region Architecture
- No visible publication dates or timestamps in the page content
- No JavaScript build step or external theme dependency

## Publish with GitHub Pages

1. Create a **public** GitHub repository named `engineering` (or another name you prefer).
2. Upload the contents of this folder to the repository root. `index.html` must be at the root.
3. Open **Settings → Pages**.
4. Under **Build and deployment**, select **Deploy from a branch**.
5. Choose branch `main` and folder `/ (root)`, then save.
6. Wait for the Pages deployment to complete. Your site will be available at `https://arson19.github.io/engineering/` if your GitHub username is `arson19` and repository name is `engineering`.

For a user/organization site at `https://arson19.github.io/`, name the repository `arson19.github.io` and put these files at its root.

## Customization

- Update the GitHub profile link if your account differs.
- Edit the HTML files directly to add articles.
- Copy an article page and update its title, description, category, content and navigation.
- Keep article slugs lowercase and use hyphens.
- The layout has no date field. Do not add dates to titles, metadata or article cards if you want to keep the public presentation timeless.

## Important

- A hidden date in the page design does not erase Git commit history, repository timestamps, hosting logs or search-engine crawl information.
- The examples are independent educational examples. Before publishing any work-related case study, code or architecture, obtain required employer approval and remove proprietary information, customer details, internal names, credentials, configuration and non-public metrics.
- Review all technical examples against the versions and practices you intend to support before presenting them as production guidance.
